Cloud Health Office on Google Cloud: production reference architecture

How a production deployment holding real member data should be built on Google Cloud: environments, network, identity, data, runtime, operations and compliance. Each component is marked with what exists in the repository today and what is scoped per engagement.

Reference design, last reviewed October 21, 2026. The same shape applies on Azure and AWS with each cloud's equivalent services. Production use requires a commercial license.

Environments

Three environments, never shared

Demonstration, sandbox and production are separate deployments with separate keys and data. Nothing in production trusts anything from the other two.

Architecture

One project per plan, private by default

Each health plan's production runs in its own Google Cloud project, whether the plan operates it or Aurelianware does. That keeps the tenant dedicated in fact, not only in configuration.

Compliance

What has to be true before real member data

  • A BAA chain: Google Cloud, the managed database provider, and every other service that touches member data.
  • The AI claims examiner: it calls an external model API. It stays off in production unless that data flow is covered by a BAA and approved by the plan.
  • A HIPAA risk analysis and documented administrative, physical and technical safeguards.
  • A penetration test before go-live, an incident response plan and on-call coverage.
  • The production readiness checklist completed, including a tested restore.
  • SOC 2 Type II as the attestation payer procurement will eventually ask for.

Getting there

The scoped work, in order

  1. Identity on Google Cloud

    Cloud KMS signing and Kubernetes service identity are in the repository. What remains is switching the manifests to Production hosts with a service account and projected token per service. See Tenant Security.

  2. Production foundation

    Terraform for the per-plan project, organization policies, private regional cluster, load balancer and WAF, CMEK and the logging project.

  3. Managed state and hardening

    Managed database, Kafka and Redis on private connections; secret store; network policies and service mesh; restore drill and penetration test.

The repository's Google Cloud notes estimate the production additions at about five to seven engineer-weeks, before plan-specific connectivity and compliance work. Hosting real member data is a decision to make with a committed health plan, not ahead of one.
