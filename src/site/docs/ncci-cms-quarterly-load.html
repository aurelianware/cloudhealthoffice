Loading CMS NCCI Edits Each Quarter

Load the public CMS PTP and MUE tables, quarter by quarter, with a ledger that makes every load repeatable.

The NCCI engine runs first in claims adjudication: procedure-to-procedure (PTP) bundling edits and medically unlikely edits (MUE) are checked before any line is priced. Cloud Health Office ships with a small built-in seed (Q1 2025, about 30 PTP pairs and 25 MUEs) for development. For real adjudication, load the CMS quarterly tables every quarter. This page covers where to get them, how to load them, and what the loader does with them.

Where to get the files

CMS publishes the Medicare NCCI tables free of charge each quarter (January, April, July and October) on its National Correct Coding Initiative edits page. Downloading requires accepting the AMA CPT license on the CMS page; the files contain CPT codes and are licensed for that use only.

TableFiles in the downloadkindsetting
PTP edits, practitionerFour tab-delimited .txt parts (…-f1.txt to …-f4.txt), plus .xlsxptppractitioner
PTP edits, outpatient hospitalTab-delimited .txt part(s), plus .xlsxptpoutpatient-hospital
MUE, practitioner services.csv (and .xlsx)muepractitioner
MUE, outpatient hospital services.csv (and .xlsx)mueoutpatient-hospital

The DME supplier MUE table and the Medicaid NCCI tables are not loaded by this loader. Unzip the download and load the .txt (PTP) or .csv (MUE) files. If you only have the .xlsx, save each sheet as CSV; the parser accepts comma-separated input with the same columns.

File layouts the parser reads

PTP files have seven columns per data row: column 1 code, column 2 code, the pre-1996 indicator, effective date (YYYYMMDD), deletion date (YYYYMMDD, or * when still active), modifier indicator (0 not allowed, 1 allowed, 9 not applicable) and the PTP edit rationale.

MUE files carry the HCPCS/CPT code, the MUE value, the MUE adjudication indicator (1 line edit, 2 date-of-service edit: policy, 3 date-of-service edit: clinical) and the rationale. When the header row is present, columns are found by name.

Both files open with a copyright and disclaimer preamble, which is skipped. After the first data row, any line that does not parse (bad code, date, modifier indicator, MUE value or adjudication indicator) is counted and reported back with its line number, and is not loaded.

Triggering a load

The benefit plan service hosts the load endpoint next to the other NCCI endpoints. It requires the service’s settings-management permission and always loads into the tenant in the caller’s token.

curl -X POST "$BENEFIT_PLAN_URL/api/v1/ncci/cms-load" \
          -H "Authorization: Bearer $TOKEN" \
          -F file=@ccipra-v324r0-f1.txt \
          -F quarter=2026Q4 \
          -F kind=ptp \
          -F setting=practitioner \
          -F part=f1

Repeat for parts f2 to f4, the outpatient hospital PTP file and the two MUE files.

FieldValues
fileThe CMS file, up to 95 MB per upload
quarterYYYYQn, for example 2026Q4
kindptp or mue
settingpractitioner or outpatient-hospital (oph is also accepted)
partOptional; use it for a table CMS splits over several files
forceOptional; true reloads a file that was already loaded

The response reports rows loaded, rows rejected with the first rejections, MUE codes the new table dropped, the file’s SHA-256 and whether it was already loaded.

What the loader does

  • Streaming. The upload is written once to a temporary file while its SHA-256 is computed, then parsed from disk and written in batches, so a full table is never held in memory. A full practitioner PTP table holds over a million rows.
  • Stable ids. PTP rows are keyed by tenant, setting, both codes and the CMS effective date; MUE rows by tenant, setting, code and quarter start. Loading the same file again replaces rows rather than duplicating them.
  • Load ledger. Each load is recorded per tenant, quarter, kind, setting and part with the file’s SHA-256 and row counts, written last. An identical re-run is a no-op, a corrected CMS re-publication (a different hash) reloads, and a load that failed part-way is retried in full.
  • PTP snapshots. Each PTP file is a full snapshot of its setting and part. Rows keep the CMS effective and deletion dates, and the deletion date is exclusive. Rows a new file omits are deleted when they came from the same quarter (a correction), or end at the quarter start when they came from an earlier quarter. Because PTP files carry full history, loading a quarter older than one already loaded for that setting is refused.
  • MUE snapshots. MUE rows carry no dates in the CMS file, so they take the quarter’s first day and end at the next loaded quarter’s start. Loading Q4 after Q1 never leaves a Q4-only code active in Q1. A load with part is not treated as a full table and reconciles nothing.
  • Settings. Practitioner rows apply to 837P claims and outpatient hospital rows to 837I claims. Seed rows apply to a setting only until a CMS table of that kind is loaded for it; after that the CMS table is authoritative. Claim types CMS publishes no table for, such as 837D, see seed rows only.
  • Version and caches. GET /api/v1/ncci/version reports the newest quarter loaded with its pair and MUE counts. Every load stamps the version, and edit lookups in every service replica re-read it at most every 60 seconds, so all claims processing uses the new tables within a minute of a load.

Operational notes

  • Load all of a quarter’s files before its effective date. Claims are edited against whatever is loaded when they adjudicate.
  • Uploads are limited to 95 MB. CMS ships the large practitioner PTP table as several part files; load each with its part.
  • A claim that fails an NCCI edit is pended for review; examiners work it as described in the pended claim guide.
