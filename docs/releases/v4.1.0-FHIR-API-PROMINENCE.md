# v4.1.0 Release Notes - FHIR API Prominence & Developer Experience

**Release Date**: February 16, 2026  
**Focus**: Commercial positioning and developer discoverability  
**Previous Version**: v4.0.0

## 📢 Overview

This release transforms Cloud Health Office's FHIR APIs from buried technical features into prominently featured commercial products. Based on comprehensive repository assessment, we've created a complete developer experience with OpenAPI specifications, quickstart guides, and a redesigned portal that positions CMS-0057-F compliance APIs as the #1 value proposition for healthcare organizations facing the January 1, 2027 deadline.

---

## 🎯 Key Changes

### OpenAPI Specifications Created

#### Patient Access API (`api/openapi/patient-access-api.yaml`)
- **Purpose**: CMS-9115-F Patient Access API compliance
- **Standards**: FHIR R4.0.1, US Core 3.1.1+, CARIN BB IG 2.0
- **Endpoints**: 
  - Patient resource search and read
  - Coverage information (active policies, historical)
  - Claims data (X12 837 Professional/Institutional)
  - Explanation of Benefits (EOB remittance details)
  - Patient $everything operation (bulk data export)
- **Security**: OAuth 2.0 with SMART on FHIR scopes
- **Interactive Viewer**: Available at SwaggerHub and built-in portal

#### Claims Scrubbing API (`api/openapi/claims-scrubbing-api.yaml`)
- **Purpose**: Pre-validation of claims before payer submission
- **Value Proposition**: Improve first-pass rates from 85% to 95%+ / Save $30-117 per prevented denial
- **Capabilities**:
  - Single claim validation
  - Batch validation (up to 500 claims/request)
  - 30+ validation rules (CPT validity, diagnosis code pairing, authorization requirements)
  - Fix recommendations with corrected values
  - Analytics API (validation trends, common errors)
- **Integration**: REST → Kafka → Argo Workflows → ElasticSearch

#### Provider Access API (Fixed)
- **Change**: Corrected filename typo (`provider-accerss-api.yaml` → `provider-access-api.yaml`)
- **Purpose**: CMS-0057-F Provider Access API compliance
- **Standards**: Da Vinci HRex, USCDI v1+

## 🔍 Technical Details

### OpenAPI Specification Standards
- **Version**: OpenAPI 3.1.0
- **Security**: OAuth 2.0 with authorization code flow
- **Examples**: Comprehensive request/response examples for all endpoints
- **Schema Validation**: FHIR R4 resource schemas embedded
- **Documentation**: Inline descriptions, required fields, field formats

### Portal Technology Stack
- **Frontend**: HTML5, CSS3 (CSS Grid), Vanilla JavaScript
- **API Viewer**: Swagger UI 5.x (embedded iframe)
- **Hosting**: Azure Static Web Apps / Kubernetes ingress
- **CDN**: GitHub Pages compatible

### Integration Architecture
```
Developer → OpenAPI Spec → Swagger UI → Try It Out
         ↓
         → Quickstart Guide → Code Example → Working App
         ↓
         → Azure AD OAuth → API Gateway → Argo Workflow on AKS
         ↓
         → Cosmos DB / FHIR Store → Response
```

## 🚀 Migration Guide

### For Existing Users

No breaking changes. All existing functionality preserved.

**New Capabilities**:
1. Visit `/api-docs.html` on your deployed portal for interactive API docs
2. OpenAPI specs available at `https://yourdomain.com/api/openapi/*.yaml`
3. Quickstart guides in repository at `api/quickstarts/*.md`

### For New Users

**Fastest Path to First API Call** (15 minutes):
1. Read [CMS-0057-F Compliance Quickstart](../../api/quickstarts/cms-0057f-compliance-quickstart.md)
2. Click "Deploy to Azure" button
3. Follow OAuth setup steps
4. Make first FHIR API call

**Building a Patient Portal** (30 minutes):
1. Read [Patient Access API Quickstart](../../api/quickstarts/patient-access-quickstart.md)
2. Configure Azure AD B2C
3. Copy/paste code examples for your language
4. Customize UI for your organization
