# Episode 012 — MongoDB cgroup evidence, before and after the CPU limit fix
#
# Captured directly from mongodb-0's /sys/fs/cgroup/cpu.stat, the same technique
# Part 10 used to diagnose claims-service/provider-service/benefit-plan-service
# throttling. See benchmark-results.txt "Bug 4" for the narrative.

## Resource spec, before fix (infrastructure/k8s/mongodb-deployment.yaml, as committed prior to PR #982)

resources:
  requests:
    cpu: "250m"
    memory: "512Mi"
  limits:
    cpu: "1000m"
    memory: "1Gi"

## cgroup cpu.stat, before fix (accumulated since mongodb-0's prior pod start —
## this is cumulative lifetime data for that pod instance, not a single-run window)

usage_usec 22994190530
user_usec 17958517913
system_usec 5035672616
nice_usec 0
nr_periods 928143
nr_throttled 120381
throttled_usec 61950174085
nr_bursts 0
burst_usec 0

Derived:
- Throttled period rate: 120,381 / 928,143 = 12.97%
- Cumulative throttled time: 61,950,174,085us ≈ 61,950s ≈ 17.2 hours
- Cumulative actual usage: 22,994,190,530us ≈ 22,994s ≈ 6.4 hours
- MongoDB spent more cumulative time throttled than it spent actually running.
